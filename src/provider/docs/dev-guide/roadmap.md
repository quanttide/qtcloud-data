## 0.0.3 要补的三块产品能力

- **review 决策文件格式**：与 CLI 侧的 manifest 契约对齐（参考 CLI 侧 docs），审核结果要有稳定的落盘格式。
- **`merge_review` 资源**：把审核结果合并回匹配明细。
- **`export` 资源**：生成最终客户交付文件。

为什么是这三块：Provider 现在跑得通，但真实业务资源还停在 `builtin:copy`——复制一遍文件，拿不出客户要的东西。这三块连起来才是「一条链路跑完，交付物到手」。

## 一条取舍：失败可观测排在哪

「扩充失败 job 的 stdout/stderr 摘要与失败步骤上下文」是体验项，不是功能项：它不新增任何能力，只决定失败那一刻操作者看到什么。

它和 0.0.2 的收紧是配套的——现在 Pipeline 失败时 HTTP 只返回泛化错误，细节进服务端日志。两者合起来，失败的操作者只能找技术同事翻日志。

排在三块能力之后，理由是人少：真实资源还停在 `builtin:copy`，会跑到失败那一步的人还不多。等交付链路真跑起来，它立刻变成高频痛点——那时它就是第一优先，不是可选项。
